# Store pane mute as server pane metadata

Supersedes the state and scope parts of ADR 0001: "local persisted state", "other computers keep independent preferences", `pane split --muted`, and the required visible indicator.

A client-local mute store needs identity keys for endpoint, session, and terminal, atomic locked writes, session freshness checks, and its own restart-reset logic. Herdr 0.9.5 already keeps display-only pane metadata on the server through `herdr pane report-metadata`. A token with a unique name such as `dotfiles_pane_mute` gets client sharing, detach survival, move and rename, pane-close cleanup, and restart reset from the server, without a server patch or wire change. The local patch shrinks to the client sound decision. Herdr keeps tokens in one flat map by token name, and `--source` does not separate names, so the unique prefix is what protects the flag from other integrations.

The cost: a mute applies to every patched client that views that server, on any computer, not to one computer only. The user accepted this. A spike (ticket 01) confirmed the token behavior with one gap: a notification can reach a client before the snapshot with the token. The user accepted this race instead of a fallback: the client reads the token only from its snapshot, so a sound can leak when the state change comes within one render interval of the mute.

Further simplifications accepted with this decision: no `pane split --muted` (the split → mute → run workflow gives the same server-side ordering guarantee: the mute is on the server before the worker starts), no new CLI commands (agents use `report-metadata` directly), no visible client indicator in this version, and an installer without its own locking, build cache, or repair command. Initial adoption on a computer with Herdr already installed is a documented manual step.
